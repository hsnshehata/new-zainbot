Changed behavior:
- `server/middleware/errorHandler.js`: payload keeps `{message,code,traceId}` and gains additive `success:false`. Unexpected failures (no explicit status, status ≥500) now return generic message `حدث خطأ غير متوقع` + code `INTERNAL_ERROR` — exception/driver strings stay server-side (logged) only. Explicit-status errors (incl. explicit 500s) keep their message/code. ValidationError→400 `VALIDATION_ERROR`, CastError→400 `BAD_ID_FORMAT` (stable). Non-API 404 still serves `public/404.html`; API 404s stay JSON.
- `server/controllers/notificationsController.js` (`testRecipient` only): every path returns an explicit `outcome: delivered|configured`. Telegram ok→`delivered`; telegram fail→400 `TELEGRAM_TEST_FAILED` (raw `reason` no longer interpolated). WhatsApp without bot→200 `success:true` + `outcome:configured` + `WHATSAPP_CONFIGURED_WITHOUT_BOT` (was misleading `success:true` "saved" with no outcome; zero sends attempted). WhatsApp with bot→`delivered` on send, single `sendDirectText` with HTML stripped. Unknown channel→400 `UNSUPPORTED_CHANNEL` (was bare `success:true`). Catch→500 `RECIPIENT_TEST_FAILED` with no `err.message` leak. Ownership unchanged (`findOne({_id,userId})` → cross-user 404, now with `RECIPIENT_NOT_FOUND` code).
- `server/controllers/integrationsController.js` (`retryWebhook` only): HTTP200 + `success:false` (transport failure OR endpoint 200-with-`success:false` body) now returns stable `code: WEBHOOK_DELIVERY_FAILED`. Retry response returns a sanitized projection (`_id/event/url/success/responseStatus/attempts/timestamp`) — raw endpoint bodies no longer ship in the response (frontend only reads `res.success`, verified in `dashboard_new.js:retryWebhook`). No-response transport errors persist `NO_RESPONSE_FROM_ENDPOINT` instead of raw axios strings. Single `axios.post` per call; `attempts+1` preserved. 404s gain additive codes (`WEBHOOK_LOG_NOT_FOUND`, `WEBHOOK_CONFIG_NOT_FOUND`); outer 500 gains `WEBHOOK_RETRY_FAILED`.
