## Fix round 1 (2026-10-05) — two Medium review findings, both fixed
- M1 (focus into inert background): `restoreFocus` preferred the closed dialog's opener even while the stack stayed open, landing focus in still-inert background that real browsers ignore. Fixed: while the stack is non-empty, focus moves into the new top dialog (its own opener only if that opener lives inside it, else its first focusable); the closed dialog's opener is restored only when the stack becomes empty.
- M2 (non-top close stole focus): closing a covered dialog moved focus to its opener. Fixed: `closeDialog` tracks `wasTop` and leaves focus untouched when the closed dialog is not top.
- Unwind-order hardening found by the new M2 test: per-entry prior-inert snapshots restored the wrong state when a lower entry closed before an upper one (upper entry's "prior" was the lower entry's isolation). Replaced with reference-counted isolation (`isolationCounts`: element → {count, original wasInert}); elements unwind to the true pre-stack state only when the last needing entry closes, in any close order.
- Tests added (2): "closing the top dialog never restores focus into the inert background" and "closing a covered dialog leaves focus untouched in the top dialog".
